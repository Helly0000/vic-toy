## 〇、第一次尝试为什么失败（**最有价值的一段，别删**）

第一次实现只往 `world` 上挂了两个财富通道（`lowerRural`/`lowerUrban`），
落地后 grep 显示它们**只出现在「初始化」和「自己的漂移」里** ——
消费、需求、不满、投资**一处都不读**。于是乡/城比是个**没有后果的读数**。

**事前探针犯的是同一个错**：它算了 `expR/expU`、让两个财富累加器漂移，
但那些财富从未回灌到消费或需求。所以 `R² = 0.115` 量的是
"两个死胡同累加器与真实经济的关系" —— 那个数**没有意义**。

> **教训：一个"新驱动"必须参与回路才有资格叫驱动。**
> 只在 `world` 上多挂两个数组，量出来的独立性是自我安慰。
> 这与 README 坑 #23「截面相关不是机制」是同一个病。
>
> 防复发的办法已经固化：`test/rural-test.js` 的 **P5「回路闭合」**
> 断言"粮食政策必须对国价产生可测影响"。谁把新通道从需求里摘掉，它就红。

### 落地时踩到的另外两个坑（也是真的，下次还会踩）

**坑 1：双重计入 ⇒ 开局标定被破坏 +73%。**
第一版用「整份 `sh[0]` 收入 ÷ 该群体自己的支出总额」算收支比，
等于每个群体都拿整份收入、却只付自己那部分人口的支出。
实测两个通道的财富一起飙到 0.92/1.87（同一省的单通道是 0.45），
底层总消费偏差 **+73%**、单省最大 **+88%**。
**修法是全程改用「人均量」口径**（人均收入 ÷ 该群体人均支出、
需求 = 人均量 × 人口），偏差回到 −0.39%，最终做到严格 no-op。

**坑 2：加性漂移 ⇒ 比值无界。**
`s` 阶层用的 `wealth += (r-1) * 0.055` 是**加性**的，Δ 是常数、两组线性发散：
乡/城比实测跑到 0.31~1.28 且最小值还在往下掉。改成**乘性**
（`wealth *= 1 + (r-1)*k`，即人口增长已在用的形式）后主体区间收在 0.97~1.25。

## 二、机制到底是什么（这是本次最有价值的发现）

乡/城分化的本质**不是**收入份额差，而是**消费篮子差 × 相对价格**：

- 乡村篮子偏口粮（`[0.66, 0.14, 0.12, 0.05, 0.03]`）
- 城市篮子偏制成品（`[0.44, 0.26, 0.18, 0.09, 0.03]`）

> ⚠ **这两套篮子有一个硬约束：逐项取平均必须恰等于 `NEEDS[0] = [0.55, 0.20, 0.15, 0.07, 0.03]`。**
> 因为 `urbanRatio` 逐省不同，只有在平均意义上相等，才能保证"开局总产出 ≈ 总消费"
> 这条标定对**每个省**都仍成立。实测最大偏差 0.00e+0（完全相等）。
> 探针当时用的城市篮子口粮项是 0.40，那会让平均值掉到 0.53 —— 落地时必须改成 0.44。
> 改这两个数组前先验算平均值，否则标定会漂。

于是**粮价相对于制成品价一涨，乡村就吃亏** —— 乡/城财富比自动成为
「粮价 vs 制成品价」这个相对价格的**读数**。而这个相对价格是经济里**现成的量**，
不是城市化的换皮。这就是它能过闸门的原因。

### 一次失败记录（值得留着，因为很容易再犯）

第一版把收入份额写成 `W_RURAL0 − W_SHIFT × indShare`，想让"城市随工业化获益"。
结果 `r(乡城比, 工业占比) = **−0.920**` —— 太高。

**根因是伪相关，不是世界耦合**：分子和分母都由 `indShare` 驱动，
同一个上游变量喂给了两根轴。这与 `ideo-derive.js` 文档里记的那条
「某些轴对必然同向，因为它们共享上游变量」是同一个病。

**修法**：去掉人为份额差，让两个群体**共用该省收入池**，分化只由篮子 + 价格产生。
修完 `r(乡城比, indShare)` 从 −0.920 掉到 **−0.301**。

### 用户假设②的量化

基建渠道是真的但**弱**：`|r(乡城比, conn)| = 0.236`、`|r(乡城比, 基建)| = 0.234`。
真正的独立杠杆是**粮食政策**：逐省配对抬升乡/城比 **+5.66%**（范围 +3.82%~+11.14%），
且抬升幅度与城市化的相关只有 **0.290** —— 也就是说它的作用**不随城市化而变**，
是个独立旋钮。

## 三、（历史）实现建议 —— **已按此落地，然后撤销**

原计划要动 `pop`（`S=3 → 4~5`），探针认为**不需要**，于是按下面这个形状落地了：

```
新增（SoA，与现有风格一致）：
  w.lowerRural : Float32Array(P)   // 乡村底层的财富
  w.lowerUrban : Float32Array(P)   // 城市底层的财富
  w.foodPolicy : Float32Array(C)   // 粮食政策 0..1（CMD_FOOD）
  BASKET_RURAL / BASKET_URBAN      // 两套消费篮子（替代 NEEDS[0]）
```

### 落地时踩到的两个坑（**这两个是真的，下次还会踩**）

**坑 1：双重计入 ⇒ 开局标定被破坏 +73%。**
第一版用「整份 `sh[0]` 收入 ÷ 该群体自己的支出总额」算收支比，
等于每个群体都拿整份收入、却只付自己那部分人口的支出。
实测两个通道的财富一起飙到 0.92/1.87（同一省的单通道是 0.45），
底层总消费偏差 **+73%**、单省最大 **+88%**。
修法是改用**人均**口径（人均收入 ÷ 该群体人均支出），偏差立刻回到 −0.39%。

**坑 2：加性漂移 ⇒ 比值无界。**
`s` 阶层用的 `wealth += (r-1) * 0.055` 是**加性**的，于是 Δ 是常数、
两个通道线性发散：乡/城比实测跑到 **0.31~1.28**，而且最小值还在往下掉
（t=60 是 0.733，t=600 已是 0.305）。改成**乘性**（`wealth *= 1 + (r-1)*k`，
即人口增长已在用的形式）能让比值有界 —— 但这一步做完之后，
才发现真正的问题不是漂移形式，而是**下面那条**。

**坑 3（决定性）：两个通道是死胡同。**
`lowerRural`/`lowerUrban` 只被「初始化」和「自己的漂移」读写，
**消费、需求、不满、投资一处都不读**。所以乡/城比没有任何后果，
它既不影响玩法也不影响其它轴 —— 事前探针之所以给了漂亮的 R²，
正是因为它也在量这个死胡同。

> **三条合起来的教训**：一个"新驱动"必须**参与回路**才有资格叫驱动。
> 只在 `world` 上多挂两个数组，量出来的独立性是自我安慰。
> 这与 README 坑 #23「截面相关不是机制」是同一个病。

## 四、必须如实记下的一个警示

同一批小样本（72 条）里，**识字率的边际参与比是 2.46 → 2.23，是下降的** ——
而在 `ideo-dof.js` 的 1800 条样本里它是 2.09 → 2.44，是上升的。

两个数都是真的，差异来自**样本量**（72 vs 1800）与**已有驱动集合**。
所以：

> **边际参与比对样本和集合敏感，不能拿一次读数当定论。**
> 准入判定要用 `ideo-dof.js` 的 1800 条大样本，小探针只用来**事前筛掉明显共线的方案**。

这也是本文件只当"事前筛"用、不当"准入结论"用的原因。
