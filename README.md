# 蒸汽与账本 · 1836

一个跑在浏览器里的**大战略经济模拟玩具**。不是游戏，是一个能点的骨架 ——
用来验证"这套架构跑不跑得动、这个经济循环好不好玩"。

一张能缩放点击的省份地图、三种阶层、五种商品、八个国家，一个每 tick 结算一次的市场。

**技术栈**：纯 JavaScript（经典 `<script>`，**不是** ES module）+ Canvas 2D + HTML/CSS。
零依赖、零构建、零安装、**零服务器**。

## 怎么跑

**双击 `index.html`。就这样。**

不需要服务器、不需要终端、不需要装任何东西。地址栏会是
`file:///.../vic-toy/index.html`。

之所以能这样，是因为全部 JS 都用**经典 `<script src>`** 加载，而且代码里
没有任何 `fetch` / `XMLHttpRequest` / ES module / Worker / localStorage。
（ES module 会被 CORS 拦掉，`file://` 下必挂 —— 选经典 script 就是为了这个。）

想用手机/平板在同一局域网里看的话才需要起服务：

```bash
cd vic-toy
python3 -m http.server 8811
# 打开 http://<你机器的局域网IP>:8811/
```

### 已知取舍与遗留

1. **地图放大后描边会变粗。** 投影/海岸线的膨胀半径在启动时烘死在贴图里，
   不再随缩放保持屏幕像素恒定。这是用观感换性能的刻意选择（省掉每帧 18 次全画布模糊）。
   默认取景下与优化前**逐像素几乎无差异**（平均通道差 0.59/255）。
   如果放大后觉得太粗，改成按缩放级别切换几档预烘贴图即可。
2. **seed 8888 不是当前最优。** 它是在修孤岛 bug **之前**的生成器下挑的；
   之后播种和存活判据都改过，现在 `node test/seed.js` 的榜首是 2718（均衡度 0.46 vs 0.35）。
   没换是因为要重跑全套视觉验证、收益不大。
3. **`file://` 未经实测。** 自动化浏览器有策略限制，打不开本地文件地址
   （报 "Cannot navigate to a file URL without local file access"），
   所以只能做代码层面的确认（见「怎么跑」）+ 用户双击验证。
4. **`render.js` / `ui.js` 没有自动化测试。** 它们依赖 DOM，回归测试覆盖不到，
   只能靠浏览器截图自查。
5. **「建什么」的权重远低于「建多快」。** 张力测试台实测：追高价（0.53M）与看禀赋（0.52M）
   几乎无差别，两者建筑数 1845 / 1849。这说明当前模型里地理禀赋只影响产量结构，
   不影响总量 —— **玩家在「选哪个商品」上花的时间，回报很低**。
   要让它变成真决策，得让商品间的收益差拉开（或让专业化有贸易出路）。
6. **按禀赋做单点专业化反而是最差的打法**（0.33M，比什么都不建的 0.23M 好不了多少）。
   原因：这是**封闭市场**，把全国产量摊薄到单一商品上，既吃不到高价、又丢了自给自足。
   README 里「比较优势 → 专业化」这个设计意图，在当前模型下**没有被兑现** ——
   这不是 bug，是结构问题，只有开了国家间贸易才会变。`test/tension.js` 会一直看着它。
7. **一局 100 年的终点是硬编码的**（`main.js` 的 `YEARS_PER_RUN`）。
   选 100 年是因为长跑实测显示约 1200 tick 后 207/214 个省全部满级、地图失去区分度；
   但这只是「当前参数下的相变点」，改了 `MAX_LEVEL` / `investCost` 就得重新量。

## 模拟了什么

一个**闭环**，不是单向的数值增长：

```
生产（建筑等级 × 地理禀赋 × 效率）
   ↓
按国清算市场 → 供需比决定价格
   ↓
各省产值 × 价格 = 收入，按阶层分配
   ↓
各阶层按财富决定消费篮子 → 支出
   ↓
收入/支出比 ──┬─→ 财富增减 ──→ 下一轮消费
              ├─→ 人口增减
              ├─→ 不满（正反馈：不满 → 减产）
              └─→ 盈余 → 投资 → 新建筑等级
```

几个刻意的设计决定：

- **三种阶层**（底层 78% / 中层 18% / 上层 4%），消费篮子完全不同 ——
  底层 55% 花在谷物上，上层 35% 花在奢侈品上。
- **工业化真的更赚钱**：每级建筑产值 农场 360 / 纺织 340 / 伐木 300 /
  机械 558 / 奢侈品 897。所以"从种粮转向造机器"在经济上有利可图 ——
  这是本作的核心张力。
- **地理禀赋**（土地肥力 / 森林 / 矿藏 / 城市化）决定各省比较优势，
  **并且参与投资打分**。没有这一条，所有省份都会追同一个高价商品，
  世界就会趋同，地图也就没意义了。
- **比较优势 → 专业化 → 贫富分化 → 不满**，这条链路让地图上的颜色差异
  有真实成因，而不是随机数。

### 3. 浏览器视觉自查 —— 改动 `render.js/ui.js` 后

⚠️ **这一步必须起本地服务器**（因为自动化浏览器打不开 `file://`）：

```bash
python3 -m http.server 8811 --bind 127.0.0.1
```

### 4. 性能测量 —— 改渲染时

**`performance.now()` 测 Canvas 会骗人。** Canvas2D 命令是排队异步光栅化的，
在 `draw()` 外面包计时器只能量到「命令提交」（约 0.3ms），看着一切正常，
实际可能卡成 27 fps。**要看 fps，也就是 rAF 的真实间隔。**

```js
// 在 main.js 的 frame() 里临时加：
var _pf = 0, _pt0 = 0;
// frame 开头：
if (!_pt0) _pt0 = now;
_pf++;
if (now - _pt0 > 2000) {
  console.log('[perf] fps=' + (_pf / ((now - _pt0) / 1000)).toFixed(1));
  _pf = 0; _pt0 = now;
}
```

**判断瓶颈在 JS 还是在填充率**：把窗口缩到一半。如果 fps 大涨 → 填充率瓶颈
（就是画得太多）；如果不变 → 环境上限或 JS 瓶颈。

**性能基线**：1680×1020 桌面窗口，任意地图模式下应稳定 **120 fps**（rAF 上限）。
掉到 30 以下说明又有人在每帧重画整张地图了。

**改完渲染后务必做逐像素对比**，确认视觉没变：

```python
from PIL import Image, ImageChops
a = Image.open("改前.png").convert("RGB").crop((640,110,2340,1280))
b = Image.open("改后.png").convert("RGB").crop((640,110,2340,1280))
d = ImageChops.difference(a, b).convert("L").histogram()
total = sum(d)
print("平均通道差", sum(i*c for i,c in enumerate(d))/total)   # 应 < 1.0
print("差异>32 占比", sum(d[33:])/total*100, "%")            # 应 ≈ 0
```

## 改之前必须知道的不变量

1. **`sim.js` 不许碰 DOM。** 这是它能在 node 里跑测试、以及未来能移植到别处的前提。
2. **tick 循环内零对象分配。** 所有累加器（`gdpAcc` / `treasuryGain` / `provCount` /
   `lowWealthAcc` / `lowPopAcc`）都预分配在 world 对象上，循环里只 `fill()` 和累加。
3. **`draw()` 必须有脏标记。** 没变化直接 return。这条一旦破坏，fps 立刻掉到 27。
4. **静态视觉元素启动时烘一次，运行时不许挂 `blur` 滤镜。**
5. **不满是全模型唯一的正反馈**（赤字 → 不满 → 减产 → 更赤字）。
   改它时必须保留「目标值模型」和 0.80 上限，否则会死亡螺旋。
6. **`NEED_FLOOR` 不能去掉。** 没有消费下限，财富反馈会把所有省份的收支比
   拉回 1，世界一片祥和，地图上什么都看不出来。
7. **Voronoi 的公共边是中垂于「站点」的，不是「质心」。** 混淆这两个会画不出国界。
8. **省份存活判据只能用 `landArea`，不能用 `landFrac`。**
   孤岛省和沿海省的胞必然大部分是海，占比一定很低，用占比会误杀它们。

## 踩过的坑（16 条）


**1. `v *= falloff` 会得到一个完美圆盘。**
第一版用"噪声 × 径向衰减"生成大陆，轮廓严格等于衰减函数的等高线。
正解是用噪声扰动距离场，并且用**二分搜索**命中目标陆地占比，而不是手调阈值。

**2. 删掉"触及边界的陆块"可能把整块大陆删光。**
陆地占比 54% 时陆地必然横跨全图、处处触边，于是全被判定为触边而删除，剩下 0.2%。
必须先靠边缘阻尼把海面收回来，这个裁剪才有意义。

**3. Voronoi 的公共边是中垂于「站点」的，不是「质心」。**
用多边形质心去求中垂线，一条边都匹配不上 —— 国界完全画不出来。
更稳的做法是从多边形的每条边反推：取边中点，最近的**其他站点**就是对面的邻居。

**4. Lloyd 松弛做满 2 次，所有胞会变成一模一样的六边形。**
看着像蜂巢，不像行政区。现在只做 1 次，之后再加一次随机扰动，
并让播种密度随噪声变化（密的地方省份小，疏的地方省份大）。

**5. 财富反馈会抹平一切差异。**
如果穷了就能无限压缩消费，所有省份的收支比都会被拉回 1。
所以加了**消费下限**：口粮砍不掉（0.85），奢侈品可以完全不买（0.10）。

**6. 不满是整个模型里唯一的正反馈。**
赤字 → 不满 → 减产 → 更赤字，一旦失衡就是死亡螺旋（实测人口 30.6M → 9.6M）。
现在用"目标值"模型而不是累加漂移，上限封死在 0.80。

**7. 别逐像素算 fbm。**
地形贴图如果 160 万像素 × 4 个八度会卡上一两秒。
在 256×160 上算完再放大插值，软斑块反而更像地形。

**8. 地图模式写死色带上限 = 看不出差别。**
现在用 92 分位数动态归一化，开局和 25 年后都有对比度。

**9. 「不属于任何国家的南极洲」——两块陆地，一块没有省份。**
地图有 2 块陆地，主大陆 57 万像素 / 179 个省份，南部那块 **5,527 像素 / 0 个省份**。
播种是约 47px 间距的抖动网格，那块岛只有 180×51 的窄条，网格点一次都没落在上面。
修法是加一步「补种」：给陆地的每个连通域打标签，没有站点的补一个。

**10. 用 `landFrac` 当存活判据，会把孤岛和沿海省一起误杀。**
补种之后那块岛**仍然**没有省份 —— 岛上的站点被 `alive` 过滤器丢掉了：
判据里有 `landFrac >= 0.28`（胞内陆地占比），而孤岛省的胞必然大部分是海。
该管的是 `landArea`（实际拥有多少陆地），不是占比。

**11. 国界过滤用「边中点在陆地上」——横穿窄岛的边会被整条丢掉。**
那条边的中垂线是竖直的，中点落在海里，过滤条件直接把它筛掉。
改成沿边 4px 采样，逐点要求「在陆地上」且「最近站点确实是这两省之一」。

**12. 「暂停着也卡」——`draw()` 无条件每帧把整张地图重新合成一遍。**
现象：fps 恒定 27.5，**跟正在做什么完全无关**。
诊断关键：窗口缩小 7 倍 → fps 从 27.5 跳到 120，确认是**填充率**瓶颈。
而 `performance.now()` **量不到**它（见「怎么验证」第 4 节）。
真实开销是每帧约 20 次全画布合成 + **18 次带 `blur` 滤镜的全画布 drawImage**。

**13. `world.tick % N === 0` 会在连续几十帧里一直为真。**
`world.tick` 只在结算时变化，条件一旦成立就持续成立到下一个 tick。
实测让地图重建次数从设计的 6/s 涨到 **30/s**，而且是突发式的 ——
这就是「最高速下卡得更明显、一顿一顿」的原因。
改成记录 `lastBuildTick`，只在 tick 真的推进且跨过间隔时重建。
**14. `Float32Array` 的初值 0 在「< 1 才衰减」逻辑里是个合法数值。**
`harvestShock` 是新增的灾情乘数，初值 0。衰减条件是 `if (harvestShock < 1)`，
于是开局把 0 当成「灾情 100%」，每 tick 都在衰减一个根本不存在的灾年 ——
**谷物价格直接飙到基准的 2.04 倍**，回归测试当场红。
教训：TypedArray 的零值只在「0 == 默认」时才是默认值；乘数类的量必须显式 `fill(1)`。

**15. 让救济去「提高财富」，等于让受救济者自己把物价推起来把自己拖垮。**
赈灾第一版写成 `wealth += 0.02` 且不设上限。跑满 100 年，底层财富从 1.18 被推到 2.51，
而**财富直接乘在消费上**（`mult = max(NEED_FLOOR, 1 + (wealth-1)*LUX_SENS)`），
于是人均支出从 5010 涨到 6540、超过收入 6114，收支比掉到 0.912 → **人口反而 −31%**。
改成「只把人托回 0.85 这条生存线、不给更多」之后，赈灾才变成一笔划算的账
（花 3.5M 换人口 +4%、国力 +13%、不满 −73%）。
教训：在一个价格由需求反推的模型里，**发钱不是中性的**；救济必须只做托底。

**16. 在「收入分配」步骤里用尚未赋值的循环变量。**
生产循环里想用国家序号取灾情乘数，写成了 `w.harvestShock[c]`，
但 `c` 要到第 2 步「供给聚合」才被赋值 —— 首 tick 是 `undefined`，
`Float32Array[undefined]` 得到 `undefined`，一路传染成 **NaN**，国库/国力全变 NaN。
教训：`sim.js` 里各步骤复用同一批循环变量（`i/p/c/g/s`）是为了零分配，
但**不能跨步骤假设它们的值**。

## 参考：这个项目的技术选型背景

**经济模型没有出处 —— 它是本仓库原创的。**
确切地说：`rng.js` / `mapgen.js` / `sim.js` 是同一晚（2026-09-13 23:31–23:58）连续写出来的，
不是从任何现成项目、论文或教科书实现移植的。下面「参考」一节讲的全是**工程选型**，
当初并没有为经济模型记录理论依据。

它的机制层是**标准经济学零件的最小实现**，逐条对应关系如下（都是启发式，不是照论文实现）：

| 模型里的机制 | 原型 | 实际关系 |
|---|---|---|
| 供需比 → 价格（`ratio^0.68` + 0.42 平滑） | 瓦尔拉斯市场出清 | 真出清要解方程组；这里是经验式 |
| 3 阶层固定预算份额（`NEEDS`） | 古典 / 斯拉法式消费倾向 | 用了骨架，三行数字是手填的 |
| 财富 → 消费弹性（`LUX_SENS`） | 恩格尔定律 | 机理相近，但这里是单参数乘子 |
| 收支比 → 人口增减 | 马尔萨斯 / 庇古效用 | 机制成立，但被 clamp 到 ±1.2%/月 |
| 禀赋（`geoBonus`）→ 比较优势 | 新经济地理学 | 是灵感不是引用，且当前未被兑现（见已知取舍 6） |
| 建筑等级 = 资本 | 古典资本积累 | 退化成 0~14 的整数档位 |

**三个结构性缺席**（理解一切「恒温器」类怪现象的关键）：**没有储蓄**（所以投资是外生速率）、
**没有货币**（国库是只进不出的单向积分器）、**没有国际贸易**（8 个封闭市场，
这正是「专业化反而最差」与「价格类政策被自愈」的根源）。另外**没有工资议价、没有信贷**。

**参数是调出来的，不是量出来的。** `BASE_LEVEL` / `WAGE_BASE` / `NEED_FLOOR` 都是手调校准，
标定目标是「开局总产出 ≈ 总消费」；`BUILDINGS[].out` 的每级产值（农场 360 / 机械 558 / 奢侈品 897）
是为了制造「工业化更赚钱」而挑的，**不是历史统计数据**。
因此：这个模型适合验证**机制设计**，不能用来支持任何关于真实经济的结论。

游戏层（三阶层、五商品、禀赋、不满、地图）明显受 Victoria 3 影响，README 也自称是它的戏仿；
但**机制层是自写的简化版**，而且把 Vic3 的核心部件（政治、法律、利益集团、贸易）全部去掉了。

---

选浏览器而不是 Godot/Unity 的理由，以及当时讨论过的东西：

- **维多利亚3 本质上 80% 是 UI**，而 HTML/CSS 做密集数据 UI 是最强的，
  恰好是 Godot 最弱的一环
- **选经典 `<script>` 而非 ES module**，就是为了保 `file://` 双击即玩
- **不用 Worker / SharedArrayBuffer**：`SharedArrayBuffer` 需要 COOP/COEP 响应头，
  纯静态托管配不了；而 `sim.js` 只有 0.14ms/tick，离需要 Worker 还远得很
- **不用 WASM**：热点不在 CPU 上，加 WASM 只会带来构建复杂度和 4GB 地址空间限制
- **不用框架**（React/Vue）：面板数量少、更新路径明确，手写 DOM + 节流更可控；
  真要上框架，市场面板那种固定行数的列表也该跳过虚拟 DOM 直接改 `textContent`

## 版本控制（2026-09 起）

本目录是独立的 git 仓库（**只在 `vic-toy/` 内，不含上级工作区**——上级还有别的项目在跑）。

```bash
git log --oneline        # 提交历史
git status               # 工作区状态
```

**给并行协作的约定**（这个项目同时有多个会话在推进）：

1. **改代码前先 `git status`。** 如果工作区不干净，说明另一个会话正在改同一块——先看清再动手。
2. **提交前必跑 `node test/check.js`**（44 项，应全绿）。它是纯逻辑层的护栏，
   挡的是"陆地有块没省份""output 变 NaN"这类会静默传播的错误。
3. **改动建造/赈灾/灾情后额外跑 `node test/tension.js 1200`**，
   确认"最好 vs 最差"的差距没有塌掉（当前基线 154%）。它挡的是"改完还是能跑，但不好玩了"。
4. **改推导公式（要素映射、意识形态轴）后跑对应的标定台**：
   `test/factor-sweep.js`（六条史实断言）、`test/ideo-derive.js`（伪相关检验）。
5. **`.gitignore` 里那两条不是随口写的**：本项目零依赖零构建是刻意的技术选型，
   `node_modules/` / `dist/` 一旦出现，说明选型跑偏了，值得停下来讨论而不是默默提交。
