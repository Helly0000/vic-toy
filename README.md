# 蒸汽与账本 · 1836

一个跑在浏览器里的**大战略经济模拟玩具**。不是游戏，是一个能点的骨架 ——
用来验证"这套架构跑不跑得动、这个经济循环好不好玩"。

一张能缩放点击的省份地图、三种阶层、五种商品、八个国家，一个每 tick 结算一次的市场。

**技术栈**：纯 JavaScript（经典 `<script>`，**不是** ES module）+ Canvas 2D + HTML/CSS。
零依赖、零构建、零安装、**零服务器**。

## 怎么跑

**双击 `index.html`。就这样。**

不需要服务器、不需要终端、不需要装任何东西。地址栏会是
`file:///.../vic-toy/index.html`。

之所以能这样，是因为全部 JS 都用**经典 `<script src>`** 加载，而且代码里
没有任何 `fetch` / `XMLHttpRequest` / ES module / Worker / localStorage。
（ES module 会被 CORS 拦掉，`file://` 下必挂 —— 选经典 script 就是为了这个。）

想用手机/平板在同一局域网里看的话才需要起服务：

```bash
cd vic-toy
python3 -m http.server 8811
# 打开 http://<你机器的局域网IP>:8811/
```

## 怎么玩

| 操作 | 效果 |
|---|---|
| 拖动地图 | 平移（拖拽不会触发选中） |
| 滚轮 | 以光标为中心缩放 |
| 点击省份 | 左侧显示它的阶层账本、产业结构、不安定程度 |
| 点击右侧排行 | 切换"当前国家"，顶栏和右下市场面板跟着切 |
| 底部地图模式 | 政治 / 人口 / 财富 / 不安定 / 工业 |
| 顶部时钟 | 暂停 · 1× · 3× · 9× · 24×（1 tick = 1 个月） |
| 悬停省份 | 弹出简表 |

**看什么**：切到「不安定」模式，暗色是太平地方，橙红是长期火药桶。
切到「工业」看哪些省份在长出烟囱。盯着右下「列国国力」看排名会不会变。

**跨国市场看哪里**：右下「市场行情」每行的数字是**本国价**，左边那个
`世 20.1` 是**世界价**。本国价高于世界价（红的）说明这个商品在本国贵、该进口；
低于世界价（绿的）说明本国生产它有优势、该出口。有贸易的月份会显示「出口 N / 进口 N」。
点右侧排行切到某个国家，左面板底部有「通商」一节：
地理可达性（地理给了你什么）、市场整合度（λ）、贸易余额（顺差还是逆差），
以及三个档位 —— 自由贸易 / 有关税 / 闭关。

## 世界线（世界即数据）

2026-09 加入。在这之前，世界只有一种来源：`mapgen.js` 用噪声造大陆。那张图好看且自洽，
但和真实地球没有任何关系 —— 冷战题材（1945–2045）于是没有落脚点：不能有"鲁尔区""巴库"，
也就没有"谁缺油"。

现在**世界是纯数据**：一个国家一行，一个省一行，一张地图是一张字符画。
加一个省是一行文本，加一个国家是五行。设计直接借自 [Fallowborn](https://github.com/dli9431/fallowborn)
（"The entire world is data… adding a province is three lines of text"）。

### 怎么用

双击 `index.html` 仍然是随机世界（行为完全没变）。换世界线用**顶栏最右的下拉框**，
它会带上 `?w=earth1945` 重新载入。命令行跑数据层：

```bash
node test/scenario-test.js     # 42 项：格式 / 地理 / 同形 / 确定性 / 经济
node test/endow-calib.js       # 量随机世界的通道分布，再验剧本是否同形
node test/earth-run.js         # 判定实验：真实世界线 vs 随机地图
```

### 一个省长什么样

```js
USA: [
  ['五大湖',   42.0,  -85.0,  16.0, { ind: 2.4, mine: 1.5 }],
  ['得克萨斯', 31.0,  -97.5,   9.0, { oil: 3.0 }],
],
```

`[省名, 纬度, 经度, 人口(百万), 要素倾斜]`。倾斜只写这个省特别的地方，
不写的默认 1 = 本国平均；写了倾斜也**不会凭空多出要素** —— 装载时会在国内按人口加权归一，
国内总量严格守恒。校验器会检查每个省有没有落在自己国家的格子里（经纬度写错当场报错）。

### 关键设计：真实要素怎么进模拟

真实数据是"某国某要素占世界份额"。要进的却是 sim 的四条禀赋通道
（`fert` / `timber` / `mineral` / `urban`），它们同时决定**效率**（`geoBonus`）与
**规模**（`levelCap`）。中间那一步是这一层唯一有技术含量的地方：

1. **人均禀赋**：`perCapita = 要素份额 ÷ 人口份额`（1.0 = 世界平均）。
   选这个定义式只因为它有一个好性质：份额各自求和为 1 → 人口加权平均的人均禀赋恒等于 1，
   不需要另做归一化。
2. **分位数锚定映射**：把 `ln(人均禀赋)` 的 p10/p50/p90 **线性地**贴到随机地图四条通道的
   p10/p50/p90 上（中位数两侧各一段斜率，因为真实分布是偏的）。

第 2 步是承重墙，不是讲究：sim 的**全部**常数（基建成本、商路衰减、天花板余量、投资曲线）
都是在随机地图上标定的，而它们全都间接依赖这四条通道的分布形状。
分布同形 → 常数继续有效；不同形 → 每一条标定都得重来。
`test/endow-calib.js` 就是这条判据的仪器，现在的实测偏差是 **0.3%**（最差 0.9%）。

> **走过的弯路（记下来免得有人再试）**：第一版用幂压缩 `perCapita ^ BETA`。
> 它只压离散度、不搬中心。实测发现随机地图上四条通道的**均值只有 0.50~0.63**
> （是 `fbm × 1.7 − 0.25` 再截断的产物，不是 1），于是剧本世界整体悬在 1.85、
> 90 分位全部顶在截断上限上，上半段完全没有区分度。幂压缩后来换成了分位数锚定。

### 世界接口：sim 只多认了五个字段

`js/sim.js` 的改动只有一处（`createWorld` 里）：
省份上如果有 `fert / timber / mineral / urban` 就用它，没有就走原来的噪声；
有 `pop0` 就用它，没有就按面积×城市化折算。外加 `opts.startYear` / `opts.intro`。

这条纪律叫**逐省判定**：随机地图的省份一个字段都不带，所以随机世界逐字节不变
（`test/scenario-test.js` 的 P7 就是在断言这件事）。同一条纪律也意味着
"接真实资源"不需要在模拟层写一行新机制 —— 换掉原料，产物自己就变了。

### 剧本世界和随机世界共用地理流水线

`js/mapgen.js` 的 `packWorld()` 是地理的后半段（站点 → Voronoi 胞 → 陆地统计 → 邻接 →
国家 → 打包）。`generate()` 和 `data/scenario.js` 的 `build()` 都调它，分叉只有三处：
国家怎么来、省份叫什么、站点推不推。

这不是洁癖，是标定的前提：如果剧本世界走另一套地理代码，那些在随机地图上标定的参数
就没有理由适用。**验证方式**是哈希 —— 这次重构后随机地图在 5 个 seed × 2 种尺寸下
逐字节不变，`tension.js` 的 242.5% 一字不差。

### 实测：真实世界线跑起来是什么样

`node test/earth-run.js`（29 国 / 199 省，跑 600 tick）：

| 问题 | 答案 |
|---|---|
| 产业结构不对称够不够强 | 均值 **0.053**，是随机地图（0.039）的 **1.36 倍**；最偏的国家最强的行业是世界平均的 **×1.92** |
| 要素上限真的在起作用吗 | **1.1%** 的（省×商品）格子顶死在天花板上，30.9% 用到七成以上，68.0% 还有余量 —— 正是"约束少数格子"的设计形状 |
| 时代解锁是不是内生的 | 机制一行不改，只把资源表从 1945 换成 1973，各国结构距离平均变动 **0.0056**（相对均值 10%）。工业位次：GBR ↓12、JPN ↑8、FRA ↓7 |
| 真实海岸线在基建层上有效吗 | t=0 时沿海 conn **0.357** vs 内陆 **0.253**（差 +0.104）；跑到 t=600 差距被压到 +0.032 —— AI 是按每级多少钱投资的，它不看连通度 |

不对称那一行从 2.05 倍掉到 1.36 倍，是加省的**代价**而不是退步：一国的结构是它各省
结构的和，省越细，一国的平均就越接近世界的平均。这个尺子量的是**国家层**的差异；
加省买到的是**省层**的粒度 —— 而贸易层、基建层、省价层全都在省这一级上工作。

### 地图细化（2026-09）

三件事，按性价比排序做的：

**① 分辨率 72×30 → 144×60（5° → 2.5°）。几乎不花力气，收益最大。**
栅格是用经纬度上的矩形生成的（`test/grid-author.py`），所以分辨率只是采样密度 ——
同一个矩形列表，格子数翻四倍。效果一眼可见：**地中海、黑海、里海、意大利、希腊、
土耳其从一坨糊里解出来了**。5° 时那一片全被抹平成一个色块。

**② 分辨率提高暴露了 6 处矩形错误 —— 这才是真正的收获。**
低分辨率会把错误藏起来：5° 时第勒尼安海、亚得里亚海、爱琴海、黎凡特海统统不到
一格宽，画不画都一样；2.5° 之后它们各占一到两格，于是那些"顺手画的"国家矩形
（意大利一路到 17°E、埃及一路到 32°N）就把整片海填成了陆地。还补上了两处从来没画过的
陆地（冰岛、菲律宾）和一段算错的国界（中国东北的矩形一路画到 135°E，
把海参崴算成了满洲）。
做法是列一份 **55 个真实经纬度的抽样点**清单，每条要么必须是海、要么必须是陆，
一个都不许错 —— 这份清单现在是 `scenario-test.js` 里的断言，不是一次性的脚本。

**③ 加省 144 → 199。这是唯一有工程量的部分，也是唯一有经济后果的部分。**
重点拆四个巨省：中国 12→31、印度 10→19、苏联 14→27、美国 13→27。
每个新省都补了要素倾斜（不补的话会**摊平**原有省的特长 —— 倾斜是在国内归一的）。

效果（同一个世界，只改省数）：

| | 144 省 | 199 省 | 随机世界 |
|---|---|---|---|
| 平均每省人口 | 172k | **125k** | 144~167k |
| 顶在 `scale` 上限的省 | 9% | **5%** | 0% |
| 平均 scale | 0.926 | **1.002** | 1.000 |
| 开局建筑级 / 百万人 | 73.3 | **107.8** | 95.5~113.1 |
| **100 年人口增长** | **×1.03** | **×1.36** | ×1.46~1.52 |

第四行是这一节的全部意义：真实地球原本 100 年人口几乎不涨。原因不是"马尔萨斯均衡"
（我先猜的是这个，被数据打回来了），而是**世界太粗**：144 个省里有 9% 顶在规模上限上，
它们的资本被钳位压住，全世界的资本密度比随机世界低 30%，于是开局的收支比正好卡在 1.0，
没有增长压力。拆细之后资本密度回到随机世界的区间，人口增长也就回来了。

**④ 顺带把省份规模的钳位变成了一条世界参数。**
`[0.35, 2.8]` 是照随机世界标定的（那里的省际人口差只有 2 倍，钳位永远够用），
而真实地球的省际人口差是 2000 倍。现在它是 `opts.scaleLo/scaleHi`，
默认值原样保留 —— 随机世界逐字节不变。剧本世界在 `data/earth1945.js` 里声明 `[0.35, 6.0]`（实测 +2%：主要那一刀是拆细省份，不是放宽钳位）。

### 已知取舍（**不是 bug，是刻意的**）

- **1945 年的简化**：29 国覆盖全部陆地，没单列的地区并入当时实际统治它的那一个 ——
  1945 本来就是帝国的世界。每条并入都写在 `data/earth1945.js` 的开头。最容易改的一处
  是北美那条直线：美加边界被拉平在 49°N，于是多伦多落在"美国"里。
- **省份密度**（2026-09 已处理，留档说明为什么）：见下面「地图细化」一节。
- **投影**：等距圆柱。1600×1000 配 360° 经度是放不下的（要 225° 纬度才等比例），
  所以南北被拉伸约 1.55 倍。这不是失误：sim 的距离是像素欧氏距离，
  而 1° 纬度恒为 111km、1° 经度在中纬度只有 ~78km —— 两者恰好抵消，
  在 30°–55° 纬度带上误差最小（那正是本作主要战场所在）。代价是高纬度的东西向距离被压扁。
- **时代表只换要素、不换人口**：1973 那张表改的是工业/石油份额，人口仍是 1945 的。

### 加一个国家 / 一个省

```js
// data/earth1945.js
codes: { ..., 'q': 'ARG' },                     // ① 挑一个没占用的字符
countries: [ { tag:'ARG', name:'阿根廷',         // ② 一个国家五行
               color:'#6f8fb8', accent:'#a4bcd8',
               factors:{ farm:5, oil:0.4, mine:0.4, wood:1, ind:1 } } ],
grid: [ '.....qqq......', ... ],                // ③ 在字符画上画出国界
provinces: { ARG: [                             // ④ 每加一个省一行
  ['潘帕斯', -35.0, -60.0, 11.0, { farm: 2.2 }],
]},
```

校验器会在 `define()` 时一次报出所有毛病（省落在别国格子上、经纬度写错、
国家在图上没有格子、要素字段缺失……），而不是修一个跑一次。
`provinces` 也接受扁平数组 `[{ n, c, lat, lon, p, t }]` —— 从别处导入数据时更方便。

### 没做（自然的下一步）

- **玩家操作** —— 已落地第一版（建造 + 赈灾），下一步可做税率与行业政策。
  注意：**价格类政策会被财富反馈自愈**（见 `vic-toy-好玩化设计.md` 的实验数据），
  要做政策就做「量」的（产能、配额、储备），别做「价」的。
- **存档 / 读档** —— 需要二进制序列化，玩具阶段故意跳过。
  好消息：玩家的全部操作都在 `world.cmd*` 环形队列里，加存档时只要存「种子 + 队列」即可。
- **封锁 / 禁运 / 阵营** —— 跨国市场与省际接入层都把管道铺好了
  （`tradeOpen` 是对外的阀门，`infra`/`conn` 是对内的），
  但「谁跟谁做不了生意」还需要一张关系矩阵。这是冷战题材真正的戏肉。
- **设施的经济意义还缺一半** —— 现在只有"路"（省↔国）。港口、管线、电站这些
  属于"一个省同时连接多个外部市场"的东西还没有位置，而那才是封锁真正要打的目标。
- **军事** —— 完全没有
- **Mod 支持** —— 这类游戏真正的命门（见 OpenTTD 的 NewGRF）。
  数据层已经把**数据**这一半铺好了（世界 = 一个 `define()` 调用），
  还缺的是沙箱方案（脚本从哪来、能碰什么），不该在玩法定型前锁死。
- **继续加省** —— 现在 199 省（中国 31、印度 19、苏联 27、美国 27），
  其余 25 国还是原来的粒度。加省的工具链已经就位（`test/grid-author.py` 出栅格、
  校验器当场报错、`endow-calib.js` 验分布），一行一个省。
  注意每加一批就要重跑 `endow-calib.js`：通道映射是按**省**拟合的，省集一变就得重验。
- **剧本切换不重启** —— 现在换世界线是 `location.href` 重新载入（最不容易留脏状态）。
  要做到无缝切换，得让 `renderer` 可重建、`world` 可替换 —— 等真有第二个剧本再说。

### 已知取舍与遗留

1. **地图放大后描边会变粗。** 投影/海岸线的膨胀半径在启动时烘死在贴图里，
   不再随缩放保持屏幕像素恒定。这是用观感换性能的刻意选择（省掉每帧 18 次全画布模糊）。
   默认取景下与优化前**逐像素几乎无差异**（平均通道差 0.59/255）。
   如果放大后觉得太粗，改成按缩放级别切换几档预烘贴图即可。
2. **seed 8888 不是当前最优。** 它是在修孤岛 bug **之前**的生成器下挑的；
   之后播种和存活判据都改过，现在 `node test/seed.js` 的榜首是 2718（均衡度 0.46 vs 0.35）。
   没换是因为要重跑全套视觉验证、收益不大。
3. **`file://` 未经实测。** 自动化浏览器有策略限制，打不开本地文件地址
   （报 "Cannot navigate to a file URL without local file access"），
   所以只能做代码层面的确认（见「怎么跑」）+ 用户双击验证。
4. **`render.js` / `ui.js` 没有自动化测试。** 它们依赖 DOM，回归测试覆盖不到，
   只能靠浏览器截图自查。
5. **「建什么」的权重远低于「建多快」。** 张力测试台实测：追高价（0.53M）与看禀赋（0.52M）
   几乎无差别，两者建筑数 1845 / 1849。这说明当前模型里地理禀赋只影响产量结构，
   不影响总量 —— **玩家在「选哪个商品」上花的时间，回报很低**。
   要让它变成真决策，得让商品间的收益差拉开（或让专业化有贸易出路）。
6. **按禀赋做单点专业化仍然是最差的打法**（0.35M），但原因已经换了。
   接入跨国市场之前，它是被**封闭市场**憋死的：产量摊薄到单一商品上，
   既吃不到高价、又丢了自给自足。接入之后价格这一环通了
   （收入对自身产出的弹性 0.546 → 0.856），可它还是垫底 ——
   现在的代价是**结构性的**：单点专业化要等很久才回本，而模型里「建多快」的权重本来就高于「建什么」，
   加上天花板把单点的上限锁死了。所以「比较优势 → 专业化」这条链路
   只是**通了**，还没有**赚头**。要让它真赚钱，下一步得动 `investCost` 的规模惩罚
   或让商品间的收益差拉开。`test/tension.js` 会一直看着它。
7. **一局 100 年的终点是硬编码的**（`main.js` 的 `YEARS_PER_RUN`）。
   选 100 年是因为长跑实测显示约 1200 tick 后 207/214 个省全部满级、地图失去区分度；
   但这只是「当前参数下的相变点」，改了 `MAX_LEVEL` / `investCost` 就得重新量。
8. **有限要素已接入，但地理约束的强度是"渐显"的。** `levelCap` 让「这个省最多能建几级
   某种厂」由地理禀赋决定，效果随人口增长逐月放大：开局顶住 0%，300 tick 6.5%，
   1200 tick 11.3%（42% 的省份至少有一项到顶）。结果是 100 年后世界的**结构分化度翻倍**
   （与关闭天花板对照：+107%），世界不再趋同。
   代价与现状：它**不掐死增长**（总人口 47.2M vs 接入前 47.3M），但也还**没有强到能决定国运**。
   调参入口：`createWorld` 的 `opts.capHeadroom`（默认 5.5，标定扫描见 `test/cap-sweep.js`）；
   效果对照见 `test/cap-effect.js`，咬合位置见 `test/cap-diag.js`。
10. **省际接入层的时间尺度是「前 50 年」，之后不再变化。**
   基建定价 380 时，AI 在 240 tick（20 年）内就把全国修到顶，之后完全静止 ——
   那会让基建退化成"开局 20 年的机制"。改成 1200（与同期的工厂 `investCost(15) ≈ 2360` 同量级）
   之后，铺开过程拉长到约 600 tick：连通度从开局的 0.231~0.427 一路爬到 0.620~0.733。
   仍然不是全程：后 60 年基建没什么可做，那时该做的是**维护 / 升级 / 被打掉**，属于还没做的部分。
11. **跨国市场在「禀赋均匀的地图」上收益很小，这是对的，不是没做出来。**
   随机地图的八个国家禀赋接近（大数定律把省级差异在国家级摊平了），
   实测把开放度从 100% 拉到 0，人均产值只差 0.4%，关税收入也只有国库的 1.8%。
   真正拉开差距的是**结构性不对称**：把最大那个国家的农场天花板压到 1 级
   （模拟「英国没有足够耕地」），闭关时粮价指数 3.04 / 人口 5.57M / 不满 0.61，
   开放时 1.22 / 9.50M / 0.09。也就是说这一层是**为 1945–2045 那条真实世界线准备的**，
   在随机地图上它更像一条保险绳而不是发动机。`test/trade-test.js` 的 P5 就是这个对照。
   另一条相关读数：一体化**没有**抹平各国的结构差异，反而放大了它（结构分化度 0.029 → 0.059）——
   统一的价格信号加上各省不同的 `geoBonus`，才让比较优势真正显形。

## 模拟了什么

一个**闭环**，不是单向的数值增长：

```
生产（建筑等级 × 地理禀赋 × 效率）
   ↓
跨国市场：世界总量 → 世界价；各国的整合度 λ 决定它跟世界价走多近
   ↓
本国价 = 国的封闭价^(1−λ) × 世界价^λ     （λ=0 就是原来的封闭市场）
   ↓
省际接入：省价 = 省的封闭价^(1−conn) × 本国价^conn
   ↓                                    （conn=0 就是"这个省自成一个世界"）
各省产值 × 价格 = 收入，按阶层分配
   ↓
各阶层按财富决定消费篮子 → 支出
   ↓
收入/支出比 ──┬─→ 财富增减 ──→ 下一轮消费
              ├─→ 人口增减
              ├─→ 不满（正反馈：不满 → 减产）
              └─→ 盈余 → 投资 → 新建筑等级
```

几个刻意的设计决定：

- **三种阶层**（底层 78% / 中层 18% / 上层 4%），消费篮子完全不同 ——
  底层 55% 花在谷物上，上层 35% 花在奢侈品上。
- **工业化真的更赚钱**：每级建筑产值 农场 360 / 纺织 340 / 伐木 300 /
  机械 558 / 奢侈品 897。所以"从种粮转向造机器"在经济上有利可图 ——
  这是本作的核心张力。
- **地理禀赋**（土地肥力 / 森林 / 矿藏 / 城市化）决定各省比较优势，
  **并且参与投资打分**。没有这一条，所有省份都会追同一个高价商品，
  世界就会趋同，地图也就没意义了。
- **比较优势 → 专业化 → 贫富分化 → 不满**，这条链路让地图上的颜色差异
  有真实成因，而不是随机数。
- **省际接入层**（2026-09 接入）：省价与本国价并行存在，由「连通度 conn」连接，
  conn 由该省的基建等级决定，基建天花板由地理（离海距离的分位 + 城市化）决定。
  这一层的形状与 VIC3 的 MAPI 同构（`Local Price = MAPI × Market Price + (1−MAPI) × State Price`），
  差别在我们用几何混合、且多串了一级。它买到的东西：**开局 212/214 个省
  至少有一项商品的省价偏离国价 >10%**（584 个格子贵、482 个便宜）——
  1836 年本来就没有"全国市场"，整个世纪的故事就是修铁路把它缝起来。
  实测修路能把本省人均产值抬 8.4%、人口抬 6.4%（`test/infra-test.js` P3）。
- **跨国市场**（2026-09 接入）：世界价与各国价并行存在，两者之间由
  「市场整合度 λ」连接。λ = 运输技术 × 通商政策 × 地理可达性 × 该商品的贸易品程度。
  没有它的时候，专业化是**不划算**的：你把全国建成农场，粮价就被自己砸下来 ——
  实测收入对自身产出的弹性只有 0.546（多产一倍只多赚 20%）。接入后是 0.856。
  这一层最要紧的性质不是「贸易让大家都变富」，而是**封锁有了牙齿**：
  一个地理上产不了粮的国家，闭关时粮价指数 3.04、人口 5.57M、不满 0.61，
  开放时是 1.22 / 9.50M / 0.09。见 `test/trade-test.js`。

### 1b. 张力测试台 —— 改动建造/赈灾/灾情后必跑

```bash
node test/tension.js 1200   # 六种打法各跑 100 年，输出对比表与「最好 vs 最差」差距
```

它回答的是**设计问题**而不是正确性问题：同一个世界换一种打法，结果差多少？
差距小就说明玩家没有真正的选择。当前基线（2026-09，跨国市场接入后）：

| 打法 | 本国国力 | 说明 |
|---|---|---|
| 不作为 | 0.24M | 什么都不建 —— 比最好的打法差 **202%** |
| 只种粮 | 0.41M | 偏执打法有代价，但不至于崩 |
| 单点专业化 | 0.35M | **按地理禀赋只建最擅长的那一种，反而最差**（见下方「已知取舍」） |
| 追高价 / 看禀赋 | 0.63M / 0.66M | 两者几乎无差别 —— **「建什么」在这套模型里权重很低，只有「建多快」重要** |
| 看禀赋 + 赈灾 | 0.72M | 花 2.6M 换人口 +2%、国力 +8%、不满 −74%，是真正的权衡 |

### 1d. 剧本数据层 —— 改动 `data/*.js` 后必跑

```bash
node test/scenario-test.js     # 42 项
node test/endow-calib.js       # 分布同形校验（这是承重墙）
node test/earth-run.js         # 判定实验：真实世界线 vs 随机地图
```

`scenario-test.js` 的八组断言里，**P3（地理抽样点）、P4（通道同形）、P7（随机世界没被污染）是承重的**：

- P3 是一份 **55 个真实经纬度**的清单，每条要么必须是海、要么必须是陆。它是唯一能
  抓住「海被填平」的判据：矩形列表在低分辨率下会掩盖这类错误 —— 5° 时第勒尼安海、
  亚得里亚海、爱琴海统统不到一格宽，画不画都一样；提到 2.5° 之后它们各占一到两格，
  不挖就会把地中海整个填平，意大利、希腊、土耳其连成一整块。
- P4 量的是剧本世界四条禀赋通道的 p10/p50/p90 与随机世界差多少。超过 6% 就说明
  `ENDOW.TARGET` 与实测的随机世界分布脱节了 —— 那时 sim 的常数对剧本世界不再成立。
- P7 断言随机地图的省份**一个剧本字段都不带**，且同 seed 的地图哈希不变。
  它防的是"把剧本字段写成默认值"这类改动：那种改动不会让任何测试变红，
  只会让随机世界悄悄漂移。

**改 `js/sim.js` 那四行 fbm 噪声之后**，先跑 `endow-calib.js`，
把打印出来的 `ENDOW.TARGET` 表粘回 `data/scenario.js`。
噪声的幅度或截断一变，通道的目标分布就变了。

### 2. 看地图形状 —— 改地图生成参数时用


### 4. 性能测量 —— 改渲染时

**`performance.now()` 测 Canvas 会骗人。** Canvas2D 命令是排队异步光栅化的，
在 `draw()` 外面包计时器只能量到「命令提交」（约 0.3ms），看着一切正常，
实际可能卡成 27 fps。**要看 fps，也就是 rAF 的真实间隔。**

```js
// 在 main.js 的 frame() 里临时加：
var _pf = 0, _pt0 = 0;
// frame 开头：
if (!_pt0) _pt0 = now;
_pf++;
if (now - _pt0 > 2000) {
  console.log('[perf] fps=' + (_pf / ((now - _pt0) / 1000)).toFixed(1));
  _pf = 0; _pt0 = now;
}
```

**判断瓶颈在 JS 还是在填充率**：把窗口缩到一半。如果 fps 大涨 → 填充率瓶颈
（就是画得太多）；如果不变 → 环境上限或 JS 瓶颈。

**性能基线**：1680×1020 桌面窗口，任意地图模式下应稳定 **120 fps**（rAF 上限）。
掉到 30 以下说明又有人在每帧重画整张地图了。

**改完渲染后务必做逐像素对比**，确认视觉没变：

```python
from PIL import Image, ImageChops
a = Image.open("改前.png").convert("RGB").crop((640,110,2340,1280))
b = Image.open("改后.png").convert("RGB").crop((640,110,2340,1280))
d = ImageChops.difference(a, b).convert("L").histogram()
total = sum(d)
print("平均通道差", sum(i*c for i,c in enumerate(d))/total)   # 应 < 1.0
print("差异>32 占比", sum(d[33:])/total*100, "%")            # 应 ≈ 0
```

## 改之前必须知道的不变量

1. **`sim.js` 不许碰 DOM。** 这是它能在 node 里跑测试、以及未来能移植到别处的前提。
2. **tick 循环内零对象分配。** 所有累加器（`gdpAcc` / `treasuryGain` / `provCount` /
   `lowWealthAcc` / `lowPopAcc`）都预分配在 world 对象上，循环里只 `fill()` 和累加。
3. **`draw()` 必须有脏标记。** 没变化直接 return。这条一旦破坏，fps 立刻掉到 27。
4. **静态视觉元素启动时烘一次，运行时不许挂 `blur` 滤镜。**
5. **不满是全模型唯一的正反馈**（赤字 → 不满 → 减产 → 更赤字）。
   改它时必须保留「目标值模型」和 0.80 上限，否则会死亡螺旋。
6. **`NEED_FLOOR` 不能去掉。** 没有消费下限，财富反馈会把所有省份的收支比
   拉回 1，世界一片祥和，地图上什么都看不出来。
7. **Voronoi 的公共边是中垂于「站点」的，不是「质心」。** 混淆这两个会画不出国界。
8. **省份存活判据只能用 `landArea`，不能用 `landFrac`。**
   孤岛省和沿海省的胞必然大部分是海，占比一定很低，用占比会误杀它们。

## 踩过的坑（33 条）


**1. `v *= falloff` 会得到一个完美圆盘。**
第一版用"噪声 × 径向衰减"生成大陆，轮廓严格等于衰减函数的等高线。
正解是用噪声扰动距离场，并且用**二分搜索**命中目标陆地占比，而不是手调阈值。

**2. 删掉"触及边界的陆块"可能把整块大陆删光。**
陆地占比 54% 时陆地必然横跨全图、处处触边，于是全被判定为触边而删除，剩下 0.2%。
必须先靠边缘阻尼把海面收回来，这个裁剪才有意义。

**3. Voronoi 的公共边是中垂于「站点」的，不是「质心」。**
用多边形质心去求中垂线，一条边都匹配不上 —— 国界完全画不出来。
更稳的做法是从多边形的每条边反推：取边中点，最近的**其他站点**就是对面的邻居。

**4. Lloyd 松弛做满 2 次，所有胞会变成一模一样的六边形。**
看着像蜂巢，不像行政区。现在只做 1 次，之后再加一次随机扰动，
并让播种密度随噪声变化（密的地方省份小，疏的地方省份大）。

**5. 财富反馈会抹平一切差异。**
如果穷了就能无限压缩消费，所有省份的收支比都会被拉回 1。
所以加了**消费下限**：口粮砍不掉（0.85），奢侈品可以完全不买（0.10）。

**6. 不满是整个模型里唯一的正反馈。**
赤字 → 不满 → 减产 → 更赤字，一旦失衡就是死亡螺旋（实测人口 30.6M → 9.6M）。
现在用"目标值"模型而不是累加漂移，上限封死在 0.80。

**7. 别逐像素算 fbm。**
地形贴图如果 160 万像素 × 4 个八度会卡上一两秒。
在 256×160 上算完再放大插值，软斑块反而更像地形。

**8. 地图模式写死色带上限 = 看不出差别。**
现在用 92 分位数动态归一化，开局和 25 年后都有对比度。

**9. 「不属于任何国家的南极洲」——两块陆地，一块没有省份。**
地图有 2 块陆地，主大陆 57 万像素 / 179 个省份，南部那块 **5,527 像素 / 0 个省份**。
播种是约 47px 间距的抖动网格，那块岛只有 180×51 的窄条，网格点一次都没落在上面。
修法是加一步「补种」：给陆地的每个连通域打标签，没有站点的补一个。

**10. 用 `landFrac` 当存活判据，会把孤岛和沿海省一起误杀。**
补种之后那块岛**仍然**没有省份 —— 岛上的站点被 `alive` 过滤器丢掉了：
判据里有 `landFrac >= 0.28`（胞内陆地占比），而孤岛省的胞必然大部分是海。
该管的是 `landArea`（实际拥有多少陆地），不是占比。

**11. 国界过滤用「边中点在陆地上」——横穿窄岛的边会被整条丢掉。**
那条边的中垂线是竖直的，中点落在海里，过滤条件直接把它筛掉。
改成沿边 4px 采样，逐点要求「在陆地上」且「最近站点确实是这两省之一」。

**12. 「暂停着也卡」——`draw()` 无条件每帧把整张地图重新合成一遍。**
现象：fps 恒定 27.5，**跟正在做什么完全无关**。
诊断关键：窗口缩小 7 倍 → fps 从 27.5 跳到 120，确认是**填充率**瓶颈。
而 `performance.now()` **量不到**它（见「怎么验证」第 4 节）。
真实开销是每帧约 20 次全画布合成 + **18 次带 `blur` 滤镜的全画布 drawImage**。

**13. `world.tick % N === 0` 会在连续几十帧里一直为真。**
`world.tick` 只在结算时变化，条件一旦成立就持续成立到下一个 tick。
实测让地图重建次数从设计的 6/s 涨到 **30/s**，而且是突发式的 ——
这就是「最高速下卡得更明显、一顿一顿」的原因。
改成记录 `lastBuildTick`，只在 tick 真的推进且跨过间隔时重建。
**14. `Float32Array` 的初值 0 在「< 1 才衰减」逻辑里是个合法数值。**
`harvestShock` 是新增的灾情乘数，初值 0。衰减条件是 `if (harvestShock < 1)`，
于是开局把 0 当成「灾情 100%」，每 tick 都在衰减一个根本不存在的灾年 ——
**谷物价格直接飙到基准的 2.04 倍**，回归测试当场红。
教训：TypedArray 的零值只在「0 == 默认」时才是默认值；乘数类的量必须显式 `fill(1)`。

**15. 让救济去「提高财富」，等于让受救济者自己把物价推起来把自己拖垮。**
赈灾第一版写成 `wealth += 0.02` 且不设上限。跑满 100 年，底层财富从 1.18 被推到 2.51，
而**财富直接乘在消费上**（`mult = max(NEED_FLOOR, 1 + (wealth-1)*LUX_SENS)`），
于是人均支出从 5010 涨到 6540、超过收入 6114，收支比掉到 0.912 → **人口反而 −31%**。
改成「只把人托回 0.85 这条生存线、不给更多」之后，赈灾才变成一笔划算的账
（花 3.5M 换人口 +4%、国力 +13%、不满 −73%）。
教训：在一个价格由需求反推的模型里，**发钱不是中性的**；救济必须只做托底。

**16. 在「收入分配」步骤里用尚未赋值的循环变量。**
生产循环里想用国家序号取灾情乘数，写成了 `w.harvestShock[c]`，
但 `c` 要到第 2 步「供给聚合」才被赋值 —— 首 tick 是 `undefined`，
`Float32Array[undefined]` 得到 `undefined`，一路传染成 **NaN**，国库/国力全变 NaN。
教训：`sim.js` 里各步骤复用同一批循环变量（`i/p/c/g/s`）是为了零分配，
但**不能跨步骤假设它们的值**。

**17. 命令队列有个参数从头到尾没人写过。**
`pushCommand(w, kind, prov, good, value)` 只有五个参数，而 `applyCommands` 里
`CMD_RELIEF` 读的是 `w.cmdCountry[i]` —— 它**从来没被写过**，永远是 0。
也就是说赈灾一直在给 0 号国发钱，不管玩家在看哪个国家。
之所以一直没暴露：张力台恰好扮演 0 号国，主循环默认选中的又正好是 0 号国（seed 8888）。
两个巧合叠在一起，把真 bug 藏了整整一版。
教训：「UI 与测试台走同一条路」还不够 —— 这条路上的**每一个参数**都要真的被走过一遍。
现在 `pushCommand` 有第六个参数 `country`，建造忽略它，赈灾与通商政策必须带。

**18. 贸易账必须**逐商品**平，不能只平总量。**
第一版用全局 `covered = min(Σ所有商品出口, Σ所有商品进口)` 去缩放两边，
「全世界出口量 = 全世界进口量」确实成立了 —— 但分商品的账不平。
而贸易余额是按世界价逐商品加权的，于是全球贸易余额合计 = 47317 而不是 0：
**凭空多出来的钱**。商品之间不能互相抵账，谷物卖不掉不能拿木材的买家来平。
现在每个商品各有一对平账系数，`test/trade-test.js` 的 P3 把这条钉死。

**19. 饱和函数会把仅有的差异压平。**
地理可达性第一版写成 `succ / (succ + A0)`，实测八个国家的 access
全落在 0.687~0.719 —— 地理几乎不起作用，等于白做。
原因是地图上八国本就首尾相连，`succ` 都差不多，再套一个饱和函数
就是把差别本身压没了。改成份额加权的 `Σ (人口份额 × exp(−距离/D0))` 之后
铺开到 0.466~0.734（λ 极差 0.35）。
教训：**先量分布，再选函数形状**；饱和/归一化是"看起来更稳"的陷阱。

**20. 测试台里的 autoInvest 会把你正在测的东西修好。**
`test/trade-test.js` 的 P1 第一版开着自动投资跑：全世界耕地砍掉 40%，
世界粮价只涨了 1.0%，看起来像价格机制失灵。
其实是 AI 在那 40 tick 里把农场又建回来了 —— 那是**另一个**要测的性质（韧劲）。
关掉之后：产出 51.8% → 价格 143%，和 `(1/0.518)^0.68 = 1.55` 同量级。
同理，「λ=0 时本国价应等于封闭价」这条断言也是错的：价格是平滑量
（`PRICE_SMOOTH`），必然滞后于每 tick 都在动的目标值，要求相等等于要求平滑器不存在。
正确写法是同一个统计量在 λ=0 与 λ>0 两个世界之间做对照。

**21. 饱和函数把差异压平 —— 我把同一个错误犯了第二次。**
省际接入层的连通度第一版写成 `conn = (0.60 + infra) / (0.60 + infra + 3.0)`，
实测全挤在 0.651~0.741，极差 0.09 —— 等于没做。
**这和当年世界层 `succ/(succ+A0)` 把 access 压成 0.687~0.719 是同一个病**：
基底给得太高，于是"一级路都没有的省"也已经 83% 接进国家市场，"路不通"就没有代价了。
教训：写任何饱和/归一化的混合系数之前，**先把它的分布量出来**。

**22. 地理量的绝对尺度会随地图大小漂。**
基建天花板第二版用 `exp(−离海距离 / 260)`，但地图是紧凑的，绝大多数省都在 200 单位以内，
指数几乎不衰减，天花板变成 8.1~17.0 的一段高平台 ——
**卡住所有人的于是变成了钱包而不是地理**，连通度重新饱和在 0.733。
改成取「离海距离在本图内的分位」才稳住：最靠海的省和最内陆的省之间一定有确定的差距。
代价是它不再是一个物理量，但天花板本来就是相对的（"这个省比那个省更适合修路"），
不是绝对的（"它值 7.3 级路"）。

**23. 截面相关不是机制。**
「连通度低的省更穷」这条判据我一连写错两次：
① 截面口径被城市化混淆（沿海省 conn 高，但它同时人口更多、人均产值被稀释）；
② 换成省内因果口径「同一个省把 conn 顶到天花板能少亏多少」，结果 ≈ 0 甚至略负 ——
因为产出侧的折价是**双向**的：效率高的省现在被低估、效率低的省现在被高估，两边的均值互相抵消。
真收益在**消费侧**（买进来的便宜了）和**专业化能力**（敢把产能压在擅长的那一样上），
那两条由 `infra-test.js` 的 P3/P4 量到（+8.4% 人均产值；粮价峰值 55.5% vs 34.2%）。
教训：机制要用「同一个体在两个状态下的对照」，截面相关只能用来提假设。

**24. 测试台里的两个错叠在一起，会伪装成产品 bug。**
「省份面板点不开」查了三轮：① `new MouseEvent('click')` 的 `offsetX` 恒为 0，
而 `render.js` 的拾取读的是 `clientX`、监听的是 `mousedown/mouseup`，
所以合成的 click 根本没进过处理函数；② 判据写成「sel-body 含『阶层』」，
而**国家概览里就有一句「查看它的阶层账本」**，于是每次点空都判成命中。
两个错各自都能让结论反过来：一个让点击永远落空，一个让落空看起来像成功。
改用 CDP 的 `Input.dispatchMouseEvent` + 判据改成「含『产业』段」之后一次通过。

**25. 一次 300 行的"等价重构"，只有哈希能证明它等价。**
把 `mapgen.generate()` 的后半段抽成 `packWorld()` 时，我论证过"调用顺序没变、
rng 序列没变"，但论证不等于事实 —— 一次 `s[j+4:]` 的切片偏移就让
generate 的收尾括号留在了 packWorld 里。**做法**：动手前先写一个哈希脚本，
把 5 个 seed × 2 种尺寸的地图签成 sha1 存下来；改完 diff，一致才算过。
最后它确实一字不差，`tension.js` 的 242.5% 也没动。这条纪律值得固化成习惯：
**凡是"应该不变"的重构，都要有一个能证明它不变的哈希。**

**26. 分位数只能对齐一个点；分布是偏的就得用两段。**
真实要素压缩成通道时，第一版是单斜率仿射映射。它能把中位数和"总跨度"钉住，
但钉不住两端 —— 森林的 p10 在中位数下方 1.28、p90 在上方 1.88，
一条直线必然一头高一头低（实测森林被整体抬高、工业被压低，各偏 5%~7%）。
改成中位数两侧各一段斜率之后，四条通道的偏差全部降到 **0.9% 以内**。
教训：要给一个分布"换形状"，先看它偏不偏；偏了就不是一个斜率的事。

**27. 归一化的分母写错，会被下游的容错悄悄吸收。**
要素倾斜要在国内归一，分母是**本国人口**。第一版写成了世界人口份额，
于是 `tn = tilt / tiltMean` 被放大 10~40 倍，人均禀赋的对数中位数跑到 3.28
（≈26 倍世界平均）。**最坏的地方是它没有报错**：分位数映射把这个荒谬的尾巴
整个压平了，四条通道照样落在合理区间，"能用"。
最后是靠 debug 打印 `ln(pc)` 的分位数才发现的。教训：
**一个错误如果被下游的归一化/截断吸收，它就不会以"崩"的形式出现，
只会以"一切正常但数字没意义"的形式出现。** 这类错只能靠打印中间量抓。

**28. 5° 栅格上，小岛屿会被自己的模糊抹掉。**
字符画 → 像素掩码要模糊两遍才能得到平滑海岸线。但日本、新西兰、尤卡坦都只有两三格宽，
3×3 均值两遍之后它们的中心值掉到 0.55 附近，再加上海岸噪声，
于是一半的孤立小岛跌破 0.5 阈值 —— **整块陆地连同省会一起从地图上消失**。
（发现方式是断言"每个省 landArea > 0"，三个省报 0。）
修法是模糊前先做一次 3×3 膨胀。但膨胀让陆地整体变胖：固定阈值 0.5 时
35.7% 的字符画会变成 **54.9%** 的像素，大西洋和地中海缩成几条缝。
所以膨胀之后必须**二分阈值**，让它回到字符画自己的陆地占比 ——
这招是从 `mapgen.js` 的大陆生成里搬来的，不靠手调。

**29. "质心在陆地上"是个坏判据。**
写剧本测试时我拿它当"没有无主之地"的判据，结果日本、墨西哥、智利、委内瑞拉、
秘鲁、哥伦比亚六个国家全部报错 —— 它们的国土分散或狭长，**平均质心本来就在海里**。
真正该断言的是 `省数 == 数据行数`：`packWorld()` 会给"没有任何站点的陆地连通域"
补种一个省，所以两者相等就精确等价于"作者手放的站点已经覆盖了每一块陆地"。
教训：判据要挑**等价**的那个，而不是"看起来相关"的那个。

**30. 分辨率会把错误藏起来 —— 所以"提高分辨率"和"修错"是同一件事。**
栅格从 5° 提到 2.5° 之后，一夜之间冒出 6 处矩形错误：意大利的矩形一路画到 17°E、
埃及的一路到 32°N，在 5° 时它们和真实海岸差半格，看不出来；到 2.5° 就把
第勒尼安海、亚得里亚海、爱琴海、黎凡特海整片填成了陆地，意大利、希腊、土耳其
连成一整块。还有两处从来没画过的陆地（冰岛、菲律宾）和一段算错的国界
（中国东北的矩形一路到 135°E，把海参崴算成了满洲）。
教训不是"要小心"，是**判据的形状**：不要等眼睛发现，要有一份
「55 个真实经纬度，每条要么必须是海要么必须是陆」的清单，改完就跑。
它现在在 `scenario-test.js` 里，不在 /tmp 里。

**31. 加省会让"国家层"的结构差异变小 —— 这是尺子的性质，不是退步。**
拆细省份之后，`earth-run.js` 的 Q1（各国产业结构与世界的距离）从随机的 2.05 倍
掉到 1.40 倍。第一反应是"加省把特长摊平了"，于是给 32 个新省补了要素倾斜 ——
结果只从 1.44 抬到 1.40（几乎没动）。
真实原因是数学的：一国的结构是它各省结构的**和**，省越细，一国的平均就越接近
世界的平均。**换尺子之前先想清楚这把尺子量的是哪一层** —— 这一把量的是国家层，
而加省买到的是省层的粒度（贸易层、基建层、省价层全在省这一级工作）。

**32. 一条被数据打回来的诊断（留档，因为第一版听起来很有道理）。**
加省之前真实地球 100 年人口只涨 ×1.03（随机世界 ×1.5）。我的第一版诊断是
"地球开局就接近它的马尔萨斯均衡，没有追赶式增长"，还配了证据：
随机世界开局收支比 0.796（穷，会增长），地球 1.009（已经在均衡上）。
听起来很顺。但顺着这个诊断往下走没有任何可做的动作 —— 它是个死胡同。
真正的病因是世界太粗：144 个省里 9% 顶在规模钳位上限上，全世界的资本密度
比随机世界低 30%。**拆细省份之后人口增长回到 ×1.36**，那个"均衡论"解释
自然就消失了。
教训：一个诊断如果只能解释现象、不能指出动作，多半还没找到底。

**33. 改一处参数之前，先量它在**这一处**还值多少。**
省份规模的钳位在 144 省时值 +18%（我在解析解里算的），在 199 省时只剩 +2% ——
因为拆细省份本身就把钳位该释放的那部分资本放出来了。
如果按 144 省时的数字去决策，会花力气去调一个已经不重要了的旋钮。

## 参考：这个项目的技术选型背景

**经济模型没有出处 —— 它是本仓库原创的。**
确切地说：`rng.js` / `mapgen.js` / `sim.js` 是同一晚（2026-09-13 23:31–23:58）连续写出来的，
不是从任何现成项目、论文或教科书实现移植的。下面「参考」一节讲的全是**工程选型**，
当初并没有为经济模型记录理论依据。

它的机制层是**标准经济学零件的最小实现**，逐条对应关系如下（都是启发式，不是照论文实现）：

| 模型里的机制 | 原型 | 实际关系 |
|---|---|---|
| 供需比 → 价格（`ratio^0.68` + 0.42 平滑） | 瓦尔拉斯市场出清 | 真出清要解方程组；这里是经验式 |
| 3 阶层固定预算份额（`NEEDS`） | 古典 / 斯拉法式消费倾向 | 用了骨架，三行数字是手填的 |
| 财富 → 消费弹性（`LUX_SENS`） | 恩格尔定律 | 机理相近，但这里是单参数乘子 |
| 收支比 → 人口增减 | 马尔萨斯 / 庇古效用 | 机制成立，但被 clamp 到 ±1.2%/月 |
| 禀赋（`geoBonus`）→ 比较优势 | 新经济地理学 | 是灵感不是引用，且当前未被兑现（见已知取舍 6） |
| 建筑等级 = 资本 | 古典资本积累 | 退化成 0~14 的整数档位 |

**三个结构性缺席**（理解一切「恒温器」类怪现象的关键）：**没有储蓄**（所以投资是外生速率）、
**没有货币**（国库是只进不出的单向积分器）、**没有国际贸易**（8 个封闭市场，
这正是「专业化反而最差」与「价格类政策被自愈」的根源）。另外**没有工资议价、没有信贷**。

**参数是调出来的，不是量出来的。** `BASE_LEVEL` / `WAGE_BASE` / `NEED_FLOOR` 都是手调校准，
标定目标是「开局总产出 ≈ 总消费」；`BUILDINGS[].out` 的每级产值（农场 360 / 机械 558 / 奢侈品 897）
是为了制造「工业化更赚钱」而挑的，**不是历史统计数据**。
因此：这个模型适合验证**机制设计**，不能用来支持任何关于真实经济的结论。

游戏层（三阶层、五商品、禀赋、不满、地图）明显受 Victoria 3 影响，README 也自称是它的戏仿；
但**机制层是自写的简化版**，而且把 Vic3 的核心部件（政治、法律、利益集团、贸易）全部去掉了。

---

选浏览器而不是 Godot/Unity 的理由，以及当时讨论过的东西：

- **维多利亚3 本质上 80% 是 UI**，而 HTML/CSS 做密集数据 UI 是最强的，
  恰好是 Godot 最弱的一环
- **选经典 `<script>` 而非 ES module**，就是为了保 `file://` 双击即玩
- **不用 Worker / SharedArrayBuffer**：`SharedArrayBuffer` 需要 COOP/COEP 响应头，
  纯静态托管配不了；而 `sim.js` 只有 0.14ms/tick，离需要 Worker 还远得很
- **不用 WASM**：热点不在 CPU 上，加 WASM 只会带来构建复杂度和 4GB 地址空间限制
- **不用框架**（React/Vue）：面板数量少、更新路径明确，手写 DOM + 节流更可控；
  真要上框架，市场面板那种固定行数的列表也该跳过虚拟 DOM 直接改 `textContent`

## 版本控制（2026-09 起）

本目录是独立的 git 仓库（**只在 `vic-toy/` 内，不含上级工作区**——上级还有别的项目在跑）。

```bash
git log --oneline        # 提交历史
git status               # 工作区状态
```

**给并行协作的约定**（这个项目同时有多个会话在推进）：

1. **改代码前先 `git status`。** 如果工作区不干净，说明另一个会话正在改同一块——先看清再动手。
2. **提交前必跑 `node test/check.js`**（44 项，应全绿）。它是纯逻辑层的护栏，
   挡的是"陆地有块没省份""output 变 NaN"这类会静默传播的错误。
3. **改动建造/赈灾/灾情后额外跑 `node test/tension.js 1200`**，
   确认"最好 vs 最差"的差距没有塌掉（当前基线 154%）。它挡的是"改完还是能跑，但不好玩了"。
4. **改推导公式（要素映射、意识形态轴）后跑对应的标定台**：
   `test/factor-sweep.js`（六条史实断言）、`test/ideo-derive.js`（伪相关检验）。
5. **`.gitignore` 里那两条不是随口写的**：本项目零依赖零构建是刻意的技术选型，
   `node_modules/` / `dist/` 一旦出现，说明选型跑偏了，值得停下来讨论而不是默默提交。
